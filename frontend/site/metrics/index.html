Stats

Panoramica
Mostra win-rate per giocatore e per commander (con filtri tipo “min partite”). Il win-rate è affidabile solo se supportato da volume (N partite).
Metriche
WR (win-rate), N (partite), confronto per ranking e grafici (bar / bubble).
Dettagli matematici
WR = wins / games wins = numero di partite vinte games = numero di partite giocate Nota: per N piccolo, WR ha alta varianza (stima instabile).
(Opzionale, futuro) shrinkage Beta-Binomial: WR_shrunk = (wins + α) / (games + α + β). Attualmente la UI usa WR grezzo + filtro “min partite”.

Meta profile

Panoramica
Valuta l’impatto al netto del tavolo: quanto un giocatore (o coppia player+commander) performa rispetto all’atteso, considerando i bracket del tavolo.
Termini
La pipeline espone OEWR (expected win residual) e lo z-score oewr_z. Vedi stats.v1.json: meta_profile_by_player, meta_profile_by_player_commander.
Dettagli matematici
Dal backend (metodo dichiarato nel JSON): oewr_method = "softmax_expected_win_residual".
Per una partita g con players i=1..m e bracket b_i: 1) Probabilità attesa di vittoria (softmax): p_i = exp(k * b_i) / Σ_j exp(k * b_j) 2) Residuo: r_i = 1 - p_i se i è il vincitore r_i = 0 - p_i altrimenti 3) Aggregazione: OEWR = media(r_i) (o somma normalizzata) sulle partite considerate 4) Standardizzazione: oewr_z = (OEWR - μ_ref) / σ_ref (μ_ref, σ_ref stimati su dataset di riferimento)
La forma esatta di aggregazione/standardizzazione è nel backend e resa esplicita dai campi meta_profile.method, oewr_method, oewr_k.

Bracket calibration

Panoramica
Stima, per ogni commander, un bracket posteriore b_post (step 0.25) che massimizza la coerenza con i risultati osservati, partendo da bracket_prior (se presente). La tabella evidenzia anche un segnale standardizzato cpr_z.
Campi
bracket_prior, b_post, b_post_sd, b_post_map, games, wins, cpr_z.
Dettagli matematici (calibrazione, molto dettagliati)
Il backend calcola un posteriore deterministico su griglia per un parametro θ (il “vero bracket” del commander) su [1, 5] con passo 0.25. Ogni occorrenza del commander è una Bernoulli (vittoria/non-vittoria) per il “pilot player”, con probabilità data dallo stesso modello softmax usato per OEWR.
Griglia θ ∈ {1.00, 1.25, ..., 5.00} Osservazioni y_i ∈ {0,1} (pilot vince?) p_i(θ) = P(y_i=1 | θ) (softmax con override del bracket del pilot a θ) Posterior (non normalizzato) log post(θ) ∝ log prior(θ) + Σ_i log Bernoulli(y_i; p_i(θ)) Prior (forma tipo normale troncata, a costante additiva) prior_mu = bracket_prior se disponibile, altrimenti 3.0 prior_sigma = 0.90 log prior(θ) = -0.5 * ((θ - prior_mu)/prior_sigma)^2 Likelihood (stabile numericamente) log Bernoulli(y;p) = log(p) se y=1, altrimenti log(1-p) con clamp p∈[1e-12, 1-1e-12]
Normalizzazione (log-sum-exp) e statistiche riportate:
Normalizzazione w(θ) = exp(log post(θ) - m) / Σ_θ' exp(log post(θ') - m) dove m = max_θ log post(θ) Output b_post = E[θ|D] = Σ_θ w(θ) * θ b_post_sd = sqrt( Var[θ|D] ) = sqrt( Σ_θ w(θ) * (θ - b_post)^2 ) b_post_map = argmax_θ log post(θ)
Interpretazione rapida:
  • b_post più alto del prior ⇒ il commander è più “forte” del bracket dichiarato (a parità di tavoli).
  • b_post_sd grande ⇒ pochi dati / evidenza debole (servono più partite).
  • cpr_z è un indicatore standardizzato: valori assoluti alti ⇒ segnale più forte.
